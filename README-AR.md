# متجر بابا صالح — حزمة التسليم الكاملة

دي النسخة الكاملة من موقع متجر بابا صالح: واجهة متجر للزبائن + لوحة تحكم لصاحب المحل + قاعدة بيانات محلية. مكتوبة بـ Node.js وقاعدة بيانات SQLite (من غير سيرفر قواعد بيانات منفصل).

المعاينة اللي اتبعتت قبل كده كانت صور ثابتة للتصفح بس. الملفات دي هي المتجر الحقيقي اللي بيستقبل طلبات فعلًا.

---

## المتجر بيعمل إيه

- واجهة عربية كاملة (RTL) بتصميم كحلي/ذهبي: أقسام (رجالي/حريمي/أولادي/بيتي/عروض)، ماركات، بحث، صفحات منتجات بمقاسات وألوان، سلة، وإتمام طلب.
- لوحة تحكم على `/admin`: إضافة وتعديل وحذف المنتجات (لحد ٦ صور للمنتج)، قائمة الطلبات وتغيير حالتها، وإعدادات المحل.
- طرق الدفع: **كاش عند الاستلام** أو **تحويل يدوي** (فودافون كاش / انستاباي) مع رفع العميل صورة التحويل. مفيش بوابة دفع بالبطاقات — ده قرار تصميم واضح، مش نقص.
- الإجمالي واضح قبل التأكيد: سعر المنتجات + الشحن = الإجمالي النهائي، من غير رسوم مخفية.

## متطلبات الاستضافة

- Node.js إصدار ٢٢ أو أحدث (الحزمة متجربة فعليًا على Node 22، وإصدار الدعم الطويل الحالي هو Node 26).
- مساحة تخزين دائمة (Persistent disk) — قاعدة البيانات وصور المنتجات بتتحفظ على القرص. استضافات الـ serverless اللي بتمسح الملفات مش مناسبة.
- ذاكرة ٥١٢ ميجا تكفي بسهولة لمحل واحد.
- بورت مفتوح (المتجر بيسمع على البورت اللي في متغير `PORT`).

ينفع على: أي VPS (Ubuntu مثلًا)، أو منصات Node اللي فيها قرص دائم، أو Docker (فيه Dockerfile جاهز).

## خطوات التشغيل على سيرفر

```bash
# 1) رفع الملفات على السيرفر (من غير مجلد node_modules لو موجود)
# 2) تثبيت المكتبات
npm install --omit=dev

# 3) متغيرات البيئة (مهمة)
export ADMIN_PASSWORD='كلمة-سر-قوية-تختارها'   # باسورد لوحة التحكم
export PORT=3000                                # البورت
export DATA_DIR=/var/lib/babasaleh              # مكان قاعدة البيانات والصور (اختياري)

# 4) التشغيل
node server.js
```

بعدها المتجر يبقى شغال على `http://عنوان-السيرفر:3000`. ربط الدومين بيتم من عند مزود الاستضافة/الدومين (A record أو reverse proxy زي nginx) — ده شغل الاستضافة العادي، مش محتاج تعديل في الكود.

**تنبيه أمان مهم:** لو `ADMIN_PASSWORD` مش مضبوط، لوحة التحكم بتقبل باسورد افتراضي ضعيف (`admin123`). لازم ضبط المتغير قبل أي تشغيل حقيقي.

## أول ما يشتغل — إعدادات لازم صاحب المحل يملاها

من لوحة التحكم ← الإعدادات:

| الإعداد | حالته دلوقتي |
|---|---|
| رقم الواتساب | رقم مؤقت `201000000000` — **لازم يتغير** لرقم المحل الحقيقي |
| بيانات التحويل (فودافون كاش/انستاباي) | نص مؤقت — **لازم رقم/حساب التحويل الحقيقي** |
| سعر الشحن | ٨٠ ج.م (قابل للتعديل) |
| اسم المحل والوصف | بابا صالح — للملابس الجاهزة |

وبعدين يضيف منتجاته الحقيقية بصورها من «المنتجات». المتجر بيبدأ فاضي عمدًا — مفيش أي منتجات تجريبية في الوضع العادي.

## النسخ الاحتياطي

كل بيانات المتجر في حاجتين:
1. ملف قاعدة البيانات `store.db` (في `DATA_DIR` أو جنب الكود)
2. مجلد `uploads/` (صور المنتجات وإيصالات التحويل)

نسخهم بشكل دوري = نسخة احتياطية كاملة.

## وضع المعاينة التجريبية (للعرض بس، مش للبيع)

- `SEED_DEMO=1` بيزرع ١٠ منتجات تجريبية بأسعار وهمية.
- `SAMPLE_PHOTOS=1` بيظهر صور ملابس توضيحية (من مكتبة صور مجانية) للمنتجات التجريبية.
- `build_static.py` بيولّد نسخة صفحات ثابتة للعرض (زي اللي اتنشرت على GitHub Pages).

دي أدوات عرض بس. التشغيل الحقيقي **من غير** المتغيرين دول: المتجر يبدأ فاضي وصاحبه يملاه.

## حدود معروفة (مش عيوب مخفية)

- الطلبات بتظهر في لوحة التحكم بس — مفيش إشعار إيميل/رسائل تلقائي للطلبات الجديدة (صاحب المحل يراجع اللوحة، أو مبرمج يضيف إشعارات بعدين).
- SQLite مناسبة جدًا لمحل واحد؛ لو حجم الطلبات بقى ضخم جدًا ممكن الترقية لقاعدة أكبر.
- صور المنتجات: حتى ٦ صور للمنتج، كل صورة لحد ٨ ميجا.

## بنية الملفات

```
server.js        تشغيل المتجر وكل المسارات (واجهة + لوحة تحكم)
views.js         صفحات الواجهة ولوحة التحكم (HTML)
db.js            إنشاء قاعدة البيانات والجداول
public/          التصميم (style.css) وصور المعاينة
Dockerfile       تشغيل بالدوكر مباشرة
package.json     المكتبات المطلوبة
build_static.py  مولّد نسخة العرض الثابتة (اختياري)
```
